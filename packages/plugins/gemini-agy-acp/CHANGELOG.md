# Changelog

## 0.2.1 — 2026-11-24

Reliable MCP tool exposure and desktop-gateway proxy support. The worker now spawns `agy acp --process-per-session` instead of `agy acp --sandbox`: the sandbox mode restricted the agent toolset and excluded the session MCP servers, so caller tools never reached the model. A session is eagerly connected to the caller's MCP server through the capability-gated `_meta.antigravity.eagerMcpServers` extension, every advertised tool carries `antigravity/alwaysLoad`, and a 18,000-token budget fitter trims only description prose (never schema keys, and it never drops a tool) to stay inside agy's customization limit. A single bounded 250 ms retry absorbs the startup "not logged in" authentication race; quota, 429 and credential failures are never retried. Desktop gateways without inherited proxy variables now resolve the configured proxy and inject it into every agy child, with a loopback `NO_PROXY` exclusion so the local MCP bridge is never proxied. Native agent tools are deliberately left enabled and no client fingerprint is spoofed. The MCP server handed to `session/new` now uses the stdio transport: the agent spawns a bundled newline JSON-RPC forwarder to the in-process loopback bridge, which works around agy's unreliable HTTP-MCP tool exposure and a Windows verbatim `\\?\` executable path that made the agent silently drop the server. The MCP handshake also answers `server/discover` and echoes the string protocol revision. Permission prompts are approved only for the caller-tool bridge and denied for every native agent tool, so the agent can never gain host command execution through an approved permission.

可靠的 MCP 工具暴露与桌面网关代理支持。worker 现在以 `agy acp --process-per-session` 而非 `agy acp --sandbox` 启动：sandbox 模式会限制 agent 工具集并排除会话 MCP 服务，导致调用方工具无法到达模型。会话通过能力门控的 `_meta.antigravity.eagerMcpServers` 扩展主动连接调用方 MCP 服务，每个工具带 `antigravity/alwaysLoad` 标记，并由 18,000 token 预算拟合器只裁剪描述文本（绝不改 schema 键、绝不丢工具）以控制在 agy 定制预算内。单次有界 250ms 重试吸收启动期「未登录」认证竞态；配额、429 与凭据失败绝不重试。无继承代理变量的桌面网关现在会解析配置代理并注入每个 agy 子进程，同时加环回 `NO_PROXY` 排除，确保本地 MCP 桥不走代理。agent 原生工具按合规要求保持启用，且不伪造客户端指纹。交给 `session/new` 的 MCP 服务改用 stdio 传输：agent 启动内置的行式 JSON-RPC 转发进程连接进程内环回桥，绕开 agy 不可靠的 HTTP MCP 工具暴露，以及 Windows verbatim `\\?\` 可执行路径导致 agent 静默丢弃服务的问题；MCP 握手同时应答 `server/discover` 并回显字符串协议版本。权限请求仅对调用方工具桥放行，对所有 agent 原生工具保持拒绝，agent 无法借获批的权限在宿主执行命令。

## 0.2.0 — 2026-11-24

Tool calling. A request that declares tools used to be rejected with `400 agy_unsupported_request`; it is now served. The plugin publishes the caller's tools to the agent through an MCP server bound to `127.0.0.1` (ephemeral port, random bearer token compared with `timingSafeEqual`), the agent raises a call, and the caller receives it as `tool_calls`. The ACP session and the MCP call stay warm, so the next request carrying the caller's results resumes the same turn instead of starting a new conversation.

The agent never executes anything: every tool result is one the caller returned, and a missing answer is reported back as an error rather than hanging the turn. The bridge descriptor, its token and the tool schemas only ever travel to the agent subprocess through `session/new` — never into a response, usage record or log. A tool set the agent cannot serve produces an explicit `400` naming the reasons instead of a silent answer. Parked calls are keyed per caller, so two interleaved conversations cannot resume each other's turn, and the default worker count is 2 because a parked call holds its worker warm.

工具调用。此前声明了工具的请求会以 `400 agy_unsupported_request` 被拒绝，现在可以正常服务：插件把调用方的工具通过只监听 `127.0.0.1` 的 MCP 服务（随机端口、随机 Bearer token，`timingSafeEqual` 比较）发布给 agent，agent 发起调用，调用方收到 `tool_calls`。ACP 会话与 MCP 调用保持存活，因此带回执行结果的后续请求会续跑同一个回合，而不是新开一段对话。

agent 不执行任何工具：每个结果都来自调用方，缺失的结果以错误回传，不会让回合无限等待。桥的描述符、token 与工具 schema 只经 `session/new` 传给 agent 子进程，绝不进入响应、用量记录或日志。agent 无法服务的工具集会得到明确的 `400` 并说明原因，而不是静默作答。挂起的调用按调用方归属，两个交错会话不会互相续跑对方的回合；默认 worker 数为 2，因为挂起的调用需要占用 worker 保温。

## 0.1.0 — 2026-11-19

Ship the connect slice. The management card now drives the whole opt-in flow over new local-only admin routes (`/api/gemini-agy-acp/status`, `/connect`, `/disconnect`, `/models/sync`, guarded by the loopback + Origin allowlist shared with the other provider plugins): Connect validates the absolute binary path, probes `agy --version` (5 s cap, 1.5.1+ required), persists the sidecar with the optional API key at 0600 and respawns the worker pool; Disconnect disables the provider and retires the workers; Model sync runs one bounded (≤5 s) temporary worker through the ACP handshake and stores the advertised model catalog. Status reports loaded/enabled/binary/version/model count, a non-reversible credential fingerprint (first 10 hex of the key's SHA-256, so operators can tell WHICH key is connected without exposing it), and the full synced model catalog behind an expandable list — without ever serializing the key. Sidecar edits apply to the next request without a gateway restart, and an explicit sidecar `apiKey` now takes precedence over the `GEMINI_API_KEY` process environment. Synced models are also written to the provider's `models` list in `config.json` (Router untouched), creating the provider entry with the managed marker if missing, and the isolated worker environment forwards standard proxy variables from the CCR process. The hand-written JSON setup instructions are replaced by the card flow; the same sidecar file remains the source of truth. When no agy is detected, the card auto-installs the official release for the current OS/architecture (pinned vendor manifest, HTTPS-only download through the gateway's proxy environment, SHA-512 verification, vendor-host payload allowlist, official default install location); the background install is single-flight with status polling, failures surface stable codes with an explicit retry, and installing never enables the provider — Connect stays the only enabling action. Per-model visibility rounds this out: model list rows show `name · id` with a hide/restore toggle plus a restore-all control, the credential line names the AI Studio key, and a new local-only `POST /api/gemini-agy-acp/models/visibility` route validates ids against the synced catalog and persists a normalized `hiddenModels` set (≤256 bounded entries) in the sidecar — hidden models stay hidden across re-syncs, ids that disappear upstream are dropped from the set silently, and the provider's registered `models` always reflect the visible catalog only. OAuth personal login rounds this out: the card gains a 登录方式 segmented toggle (API key / Google 账号) persisted per connect call, Google-account mode hides the key input entirely and Connect verifies the CLI's real OS-keyring browser login with one bounded ACP handshake (authenticate + session/new) on a temporary worker of the selected binary — `--version` alone cannot prove the login — mapping any handshake failure to a stable terminal sign-in hint. The account email shown on the card comes exclusively from that verified handshake (explicit ACP account metadata, or the verifying child's own bounded captured diagnostics; never stale log files, token stores or other processes' state) and the card shows 账号邮箱未提供 when the CLI provides none. oauth-personal pools spawn on a fresh temporary working directory with a whitelist of only runtime/login-required environment variables — never a blanket `process.env` copy, and never credential variables such as `GEMINI_API_KEY` — while API-key pools keep the fully isolated environment; `settings` rejects any apiKey alongside oauth-personal, switching modes evicts the other mode's stored credential/stale account email, and model sync works without any key in Google-account mode.

新增连接闭环。管理卡片通过全新的仅限本地的管理路由（`/api/gemini-agy-acp/status`、`/connect`、`/disconnect`、`/models/sync`，沿用其他供应商插件的回环 + Origin 白名单守卫）驱动完整启用流程：连接会校验 binary 绝对路径、探测 `agy --version`（5 秒上限，要求 1.5.1+）、把可选 API key 以 0600 权限写入 sidecar 并重建 worker 池；断开停用供应商并回收 worker；同步模型以一个 ≤5 秒的临时 worker 完成 ACP 握手并保存 CLI 公布的模型目录。状态行展示 loaded/enabled/binary/version/模型数量、不可逆的凭据指纹（key 的 SHA-256 前 10 位，便于确认连的是哪把钥匙而不暴露密钥），以及可展开的完整已同步模型列表，且从不序列化密钥。sidecar 修改无需重启网关即可在下一个请求生效；显式的 sidecar `apiKey` 优先于进程环境变量 `GEMINI_API_KEY`。同步出的模型会写入 `config.json` 供应商条目的 `models`（不动 Router）；隔离 worker 环境会转发 CCR 进程的标准代理变量。手工 JSON 配置说明由卡片流程取代，sidecar 文件仍是唯一配置来源。未检测到 agy 时，卡片按当前系统/架构自动安装官方发布版（固定厂商清单、仅 HTTPS 且继承网关代理环境、SHA-512 校验、载荷域名白名单、官方默认安装位置）；后台安装单飞执行并由卡片轮询状态，失败显示稳定错误码与显式重试，安装绝不启用供应商——连接仍是唯一的启用操作。模型级可见性补全了这一环：模型列表行展示 `name · id` 并带隐藏/恢复切换与一键全部恢复，凭据行标明 AI Studio key；新增仅限本地的 `POST /api/gemini-agy-acp/models/visibility` 路由对照已同步目录校验 id，并把规范化的 `hiddenModels`（≤256 条有界条目）持久化到 sidecar —— 重新同步后隐藏集合保留，上游消失的 id 会被静默清理，供应商注册的 `models` 始终只反映可见目录。Google 账号个人登录补全了这一环：卡片新增登录方式分段切换（API key / Google 账号），随每次连接持久化；Google 账号模式完全隐藏密钥输入框，连接时以选中 binary 的一个有界真实 ACP 握手（authenticate + session/new）验证 CLI 自身的 OS 钥匙串浏览器登录（仅 `--version` 无法证明登录有效），任何握手失败都会映射为稳定的「请先在终端运行一次 agy 完成浏览器登录」提示。卡片展示的账号邮箱只来自本次已验证的握手（显式 ACP 账号元数据，或验证子进程自身有界捕获的诊断输出；绝不读取陈旧日志文件、令牌存储或其他进程的状态），CLI 未提供时显示「账号邮箱未提供」。oauth-personal 工作进程在全新的临时工作目录上、以仅含运行/登录所需环境变量的白名单启动——绝不透传全量 `process.env`，也绝不传递 `GEMINI_API_KEY` 等凭据变量；API key 池仍使用完全隔离环境；`settings` 拒绝 oauth-personal 携带任何 apiKey，切换模式会清除另一模式存储的凭据或陈旧账号邮箱，Google 账号模式下同步模型无需任何密钥。

## 0.0.3 — 2026-11-19

Restyle the management card to match the other provider cards: the host settings page stylesheet (Tailwind utilities plus the custom glass-card rule) now drives the look, with the shared container, header, badge variants and section styling. Setup instructions are collapsed by default. The authentication badge identifies API-key billing.

管理卡片样式与其他供应商卡片对齐：改用宿主设置页样式表（Tailwind 工具类与自定义 glass-card 规则），容器、头部、徽章与分区样式保持一致。配置说明默认折叠，认证徽章标明使用 API key 计费。

## 0.0.2 — 2026-11-19

Ship a read-only management card. The settings page reports a card load failure for every enabled plugin without one, so the previous release showed a misleading reinstall hint. The card explains the local opt-in contract and requires no network access.

新增只读管理卡片。设置页会把所有未提供卡片的已启用插件报告为「卡片加载失败」，因此上一版会显示误导性的重装提示。卡片仅说明本地启用方式，不访问网络。

## 0.0.1 — 2026-11-19

First public experimental release. Route text chat and streaming responses through a local Antigravity CLI worker using ACP and Gemini API-key authentication. The plugin requires explicit opt-in. Testing used simulated workers. Production CLI authentication remains to be verified.

首个公开实验版本。插件通过 ACP 和 Gemini API key 认证调用本地 Antigravity CLI，支持文本对话与流式响应，需显式启用。测试使用模拟进程，真实 CLI 的认证仍待验证。
