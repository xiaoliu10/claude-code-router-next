# Changelog

## 0.1.0 — 2026-11-19

Ship the connect slice. The management card now drives the whole opt-in flow over new local-only admin routes (`/api/gemini-agy-acp/status`, `/connect`, `/disconnect`, `/models/sync`, guarded by the loopback + Origin allowlist shared with the other provider plugins): Connect validates the absolute binary path, probes `agy --version` (5 s cap, 1.5.1+ required), persists the sidecar with the optional API key at 0600 and respawns the worker pool; Disconnect disables the provider and retires the workers; Model sync runs one bounded (≤5 s) temporary worker through the ACP handshake and stores the advertised model catalog. Status reports loaded/enabled/binary/version/model count, a non-reversible credential fingerprint (first 10 hex of the key's SHA-256, so operators can tell WHICH key is connected without exposing it), and the full synced model catalog behind an expandable list — without ever serializing the key. Sidecar edits apply to the next request without a gateway restart, and an explicit sidecar `apiKey` now takes precedence over the `GEMINI_API_KEY` process environment. Synced models are also written to the provider's `models` list in `config.json` (Router untouched), creating the provider entry with the managed marker if missing, and the isolated worker environment forwards standard proxy variables from the CCR process. The hand-written JSON setup instructions are replaced by the card flow; the same sidecar file remains the source of truth. Per-model visibility rounds this out: model list rows show `name · id` with a hide/restore toggle plus a restore-all control, the credential line names the AI Studio key, and a new local-only `POST /api/gemini-agy-acp/models/visibility` route validates ids against the synced catalog and persists a normalized `hiddenModels` set (≤256 bounded entries) in the sidecar — hidden models stay hidden across re-syncs, ids that disappear upstream are dropped from the set silently, and the provider's registered `models` always reflect the visible catalog only. OAuth personal login rounds this out: the card gains a 登录方式 segmented toggle (API key / Google 账号) persisted per connect call, Google-account mode hides the key input entirely and Connect verifies the CLI's real OS-keyring browser login with one bounded ACP handshake (authenticate + session/new) on a temporary worker of the selected binary — `--version` alone cannot prove the login — mapping any handshake failure to a stable terminal sign-in hint. The account email shown on the card comes exclusively from that verified handshake (explicit ACP account metadata, or the verifying child's own bounded captured diagnostics; never stale log files, token stores or other processes' state) and the card shows 账号邮箱未提供 when the CLI provides none. oauth-personal pools spawn on a fresh temporary working directory with a whitelist of only runtime/login-required environment variables — never a blanket `process.env` copy, and never credential variables such as `GEMINI_API_KEY` — while API-key pools keep the fully isolated environment; `settings` rejects any apiKey alongside oauth-personal, switching modes evicts the other mode's stored credential/stale account email, and model sync works without any key in Google-account mode.

新增连接闭环。管理卡片通过全新的仅限本地的管理路由（`/api/gemini-agy-acp/status`、`/connect`、`/disconnect`、`/models/sync`，沿用其他供应商插件的回环 + Origin 白名单守卫）驱动完整启用流程：连接会校验 binary 绝对路径、探测 `agy --version`（5 秒上限，要求 1.5.1+）、把可选 API key 以 0600 权限写入 sidecar 并重建 worker 池；断开停用供应商并回收 worker；同步模型以一个 ≤5 秒的临时 worker 完成 ACP 握手并保存 CLI 公布的模型目录。状态行展示 loaded/enabled/binary/version/模型数量、不可逆的凭据指纹（key 的 SHA-256 前 10 位，便于确认连的是哪把钥匙而不暴露密钥），以及可展开的完整已同步模型列表，且从不序列化密钥。sidecar 修改无需重启网关即可在下一个请求生效；显式的 sidecar `apiKey` 优先于进程环境变量 `GEMINI_API_KEY`。同步出的模型会写入 `config.json` 供应商条目的 `models`（不动 Router）；隔离 worker 环境会转发 CCR 进程的标准代理变量。手工 JSON 配置说明由卡片流程取代，sidecar 文件仍是唯一配置来源。模型级可见性补全了这一环：模型列表行展示 `name · id` 并带隐藏/恢复切换与一键全部恢复，凭据行标明 AI Studio key；新增仅限本地的 `POST /api/gemini-agy-acp/models/visibility` 路由对照已同步目录校验 id，并把规范化的 `hiddenModels`（≤256 条有界条目）持久化到 sidecar —— 重新同步后隐藏集合保留，上游消失的 id 会被静默清理，供应商注册的 `models` 始终只反映可见目录。Google 账号个人登录补全了这一环：卡片新增登录方式分段切换（API key / Google 账号），随每次连接持久化；Google 账号模式完全隐藏密钥输入框，连接时以选中 binary 的一个有界真实 ACP 握手（authenticate + session/new）验证 CLI 自身的 OS 钥匙串浏览器登录（仅 `--version` 无法证明登录有效），任何握手失败都会映射为稳定的「请先在终端运行一次 agy 完成浏览器登录」提示。卡片展示的账号邮箱只来自本次已验证的握手（显式 ACP 账号元数据，或验证子进程自身有界捕获的诊断输出；绝不读取陈旧日志文件、令牌存储或其他进程的状态），CLI 未提供时显示「账号邮箱未提供」。oauth-personal 工作进程在全新的临时工作目录上、以仅含运行/登录所需环境变量的白名单启动——绝不透传全量 `process.env`，也绝不传递 `GEMINI_API_KEY` 等凭据变量；API key 池仍使用完全隔离环境；`settings` 拒绝 oauth-personal 携带任何 apiKey，切换模式会清除另一模式存储的凭据或陈旧账号邮箱，Google 账号模式下同步模型无需任何密钥。

## 0.0.3 — 2026-11-19

Restyle the management card to match the other provider cards: the host settings page stylesheet (Tailwind utilities plus the custom glass-card rule) now drives the look, with the shared container, header, badge variants and section styling. Setup instructions are collapsed by default. The authentication badge identifies API-key billing.

管理卡片样式与其他供应商卡片对齐：改用宿主设置页样式表（Tailwind 工具类与自定义 glass-card 规则），容器、头部、徽章与分区样式保持一致。配置说明默认折叠，认证徽章标明使用 API key 计费。

## 0.0.2 — 2026-11-19

Ship a read-only management card. The settings page reports a card load failure for every enabled plugin without one, so the previous release showed a misleading reinstall hint. The card explains the local opt-in contract and requires no network access.

新增只读管理卡片。设置页会把所有未提供卡片的已启用插件报告为「卡片加载失败」，因此上一版会显示误导性的重装提示。卡片仅说明本地启用方式，不访问网络。

## 0.0.1 — 2026-11-19

First public experimental release. Route text chat and streaming responses through a local Antigravity CLI worker using ACP and Gemini API-key authentication. The plugin requires explicit opt-in. Testing used simulated workers. Production CLI authentication remains to be verified.

首个公开实验版本。插件通过 ACP 和 Gemini API key 认证调用本地 Antigravity CLI，支持文本对话与流式响应，需显式启用。测试使用模拟进程，真实 CLI 的认证仍待验证。
