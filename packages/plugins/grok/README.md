# Grok Build subscription provider

Experimental coreApi=1 plugin for the separately installed [Grok Build CLI](https://x.ai/cli). Uses the subscription backend at `https://cli-chat-proxy.grok.com/v1/responses`, not xAI API-key billing. Install the built package as a local provider plugin; its settings card supports device sign-in, explicit current-CLI import, model sync, hide/restore, quota and disconnect. No credentials are read on activation; status reads only CCR's private file. Nothing automatically installs or signs into the CLI.

Device login runs `grok login --device-auth` in a new private CCR home and expires after ten minutes. The authorization page must be `https://accounts.x.ai/oauth2/device?user_code=...`; on macOS/Windows the CLI opens it itself. Current CLI import reads `GROK_HOME/auth.json` (default `~/.grok/auth.json`) only after the explicit action. Discovery supports absolute `GROK_BIN_DIR`, `GROK_HOME/bin`, `~/.grok/bin`, then PATH/`~/.local/bin` only when resolved under `/.grok/`. Account identity uses email, user ID or JWT subject. One connected account per activation; disconnect before replacing it. Refresh models explicitly after connecting; no guessed model IDs are inserted.

The official CLI owns rotating refresh tokens. Near expiry, or once after a 401, CCR runs `grok models` in the selected home and rereads credentials. An unchanged rejected token requires reconnecting; for an imported shared home, opening Grok Build and sending a message can help. CCR and other processes sharing a home can race on refresh rotation; do not concurrently use CPA with the same account. Disconnect removes CCR state and owned private homes, preserves shared CLI credentials, and does not revoke server tokens.

Credentials and CLI-home ownership metadata live outside the installed plugin payload in `grok-credentials.json` under the host config directory, atomically written with mode 0600. Private CLI homes live in `grok-homes/` (0700). Secrets never enter config, status or the card. Back up and protect the CCR config directory. The managed provider is `grok-subscription`, with marker `ccr-managed-grok`; raw config writes preserve environment placeholders and unrelated providers/Router. A host with `readRawConfig` is required for management operations.

All HTTP lanes use the host subscription dispatcher with redirects disabled. Child CLI processes scrub credential overrides and ambient proxy variables, and receive only the explicit `SUBSCRIPTION_PROXY_URL` setting (a literal or `$ENV_NAME`). `PROXY_URL` is never inherited. No X search is auto-injected. Explicit unsupported tool restrictions fail closed. Grok models come only from `/models`; context variants retain stable plain IDs and use `@500k` suffixes mapped to context headers. Quota missing/error is unknown; stale last-known readings are labeled and do not override a recent 429 cooldown.

## Success healing

Latched account state (relogin/expired, rate cooldown) clears only on a validated successful upstream exchange — never on a mere HTTP 200. A data-plane stream must reach a legitimate terminal (`response.completed` / `response.incomplete`); a non-stream 200 must actually be a Responses JSON object; a model sync must produce a non-empty list; a quota read must be well-formed (a zero used-percent reading is legitimate, missing fields are not). Failed exchanges, truncated streams, error events and malformed quota leave the latches untouched, so a billing outage can never mask an active 429 cooldown and a 200 SSE carrying a failure never clears a relogin latch. The rate cooldown itself is time-based by design: while it holds, data-plane requests are refused before network, and healing flows through the service's own validated exchanges (the card's model-sync/quota actions), which are exactly the lanes that survive it.

## State mutation ordering

All durable writes (credential refresh, model sync, model visibility) flow through one serialized mutation chain. Every job merges into the latest durable state at execution time, so a credential refresh racing a model sync can never overwrite synced models with a stale snapshot, and a model mutation can never drop a just-rotated credential. If a config write succeeds but the private persist fails, the managed config entry is rolled back to its pre-mutation state; shared CLI credentials are never touched by any of these paths. Disconnect drains the chain before removing the credential file, so no queued writer can resurrect it. Upstream 403 (network, region or permission) is classified as a plain upstream error and never flips the account to expired — only a 401 does — and send-level failures classify as a retryable 502 rather than an account-invalid reading.

## Server lifecycle and restart gap

All mutable engine state (torn-read cache, renewal single-flight, CLI version cache, pending child registry) lives in a per-activation `createGrokEngine` factory instance — never in module globals — so two Server instances or re-activations share nothing. The host PluginContext API has no disposal hook and the registry does not dispose runtimes, so cleanup paths are the ones this plugin owns: `disconnect` and `login/cancel` kill pending CLI children, abort in-flight model/billing fetches and remove owned private homes. If the CCR process exits or restarts mid-login, the bounded login CLI child ends on its own timeout and an orphaned `grok-homes/<id>` directory can remain; it is inert (only an active login job trusts an owned home) but is not auto-removed on restart — delete it manually or ignore it. Restart does not resurrect credentials: state is re-read from the 0600 file, and a mid-restart disconnect that already removed it stays removed. Expanding the core disposal API is out of scope for this plugin.

The provider chain is `['openai-responses', 'grok']`. The host owns Chat/Anthropic ↔ Responses conversion. Grok normalizes encrypted reasoning include, function schemas, collaboration history, model/window and session metadata, and checks SSE terminal/EOF while preserving bytes and upstream cancellation. Terminal in-stream evidence is classified, not flattened: quota signals (`rate_limit*`/`usage_limit*`/429) cool the account, auth signals (`invalid_token`/401/unauthorized) mark relogin, and anything else is a generic upstream failure; a legitimate `response.incomplete` output cap is a whole reply (the host maps it to a length finish reason). It does not execute client tools. See THIRD_PARTY_NOTICES.md for pinned MIT extraction provenance and local changes.

Build/check from this directory: `pnpm exec tsc --noEmit -p tsconfig.json`, `pnpm test`, `pnpm build`. Tests use isolated temporary homes, fake CLI scripts and strict mocked fetch, with no fallback or real account access. Real subscription login, refresh, hosted tools, image inference, billing and generation have not been validated. CLI renewal can fail upstream even for a future-dated token. Host protocol behavior remains the integration boundary; this package does not bundle or replace host converters. Integration requires the current host Responses converter with `responseTargetFormat` support (the older core converter silently mishandles Chat/Anthropic native Responses streams). Current host `normalizeResponsesBody` can discard encrypted reasoning items, collaboration/custom history and `include` before the Grok transformer sees them; direct Grok postprocessing preserves these fields when supplied, but full opaque native-history roundtrips are not established. Client abort reaches the plugin stream reader when the host cancels it; socket-disconnect → upstream-fetch abort is still host-owned and not proven by the plugin fixtures.
